# ci-quality-gates - Intent and Specifications

## Summary
Усилить CI тремя согласованными изменениями: тесты фронтенда, защита dev, проверка зависимостей.
## Problem
Сборка интерфейса не проверяет пользовательские сценарии; успешный CI не обязателен для слияния; зависимости не проверяются на известные уязвимости.
## Scope
Модульные и браузерные тесты фронтенда в CI, govulncheck и npm audit, обязательные проверки и PR для dev.
## Out of Scope
CD, развёртывание, изменения бизнес-логики и интерфейса, защита остальных веток.
## Constraints
Сохранить существующие проверки Go и Docker. Не изменять рабочие данные и посторонние локальные файлы.
## Success Criteria
- CI запускает все существующие тесты фронтенда и сохраняет диагностику браузерных сбоев.
- Уязвимости Go в используемом коде и npm уровня high/critical блокируют CI.
- dev требует PR и успешные проверки Go, frontend, security и Docker.
- Локальные проверки и результаты настройки GitHub проверены; ограничения явно описаны.
## Decisions
Существующее одобрение пользователя «давай первые 3 пункта» определяет объём работ. Используем Chromium Playwright, Node 24 и существующую версию Go из go.mod. Проверяем все npm-зависимости, включая инструменты сборки. Не требуем дополнительного ревьюера в команде из трёх человек. Защита распространяется на администраторов; прямые пуши и force push запрещены.
## Open Questions
Нет продуктовых вопросов. Доступность защиты и найденные уязвимости проверяются при выполнении.
