# Запас — умная копилка

[![CI](https://github.com/keepmeinyourmind/zapas/actions/workflows/ci.yml/badge.svg?branch=dev)](https://github.com/keepmeinyourmind/zapas/actions/workflows/ci.yml)

**Копилка, которая откладывает не процент от дохода, а безопасную сумму.**

Проект для конкурса «Академия Финтеха 2026» (ВТБ + Финансовый университет), трек «Финтех без границ: банк будущего для бизнеса и клиентов».

## Проблема

Автопополнение копилки откладывает фиксированный процент от каждого поступления и не смотрит, что будет дальше. У молодёжи 18–22 лет доход нерегулярный: подработка, стипендия, фриланс. Месяц с просевшим доходом и платежом по рассрочке, а копилка уже списала свою долю. Денег на платёж не хватает, человек лезет в кредитный лимит, и копилка начинает вредить.

## Идея

«Запас» считает, сколько можно отложить **безопасно**: процент от дохода после обязательных платежей и повседневных трат до следующего дохода. Если всё как обычно, он переводит деньги сам. Если доход изменился или впереди крупный платёж, он ничего не списывает молча, а **спрашивает клиента** и предлагает безопасную сумму. Каждое решение сопровождается причиной простым языком.

### Пример: Аня, 20 лет, студентка

Подработка 25 000 ₽ и стипендия 5 000 ₽, цель «Подушка», откладывать 10%. Через 5 дней рассрочка за ноутбук 6 000 ₽.

| | Обычная копилка | Запас |
|---|---|---|
| Пришло 24 000 ₽ (меньше обычного) | молча списала 2 400 ₽ | спросил: «Доход ниже обычного, впереди платёж. Отложить 1 000 ₽?» |
| Платёж по рассрочке | не хватило 1 400 ₽ | прошёл без проблем |

Если клиент не ответил за 24 часа, срабатывает самый безопасный вариант: минимальная сумма или пропуск.

## Как принимается решение

1. Классификатор решает, доход ли это поступление. Возврат, кредит и перевод из копилки обратно на карту **не доход**: иначе получится цикл.
2. Профиль дохода: медиана за 3–6 месяцев, отклонение этого месяца, уровень доверия. У нового клиента без истории система всегда спрашивает.
3. Безопасная сумма = собственные деньги на карте − предстоящие платежи − буфер. Кредитный лимит не учитывается.
4. Движок выбирает действие:

| Действие | Когда |
|---|---|
| `auto` | доход в пределах обычного, безопасной суммы хватает |
| `ask` | доход упал более чем на 15%, впереди платёж, мало истории, пришла премия, доход такого вида пришёл впервые |
| `skip` | не доход, копилка на паузе, цель достигнута (или до неё меньше 100 ₽), сумма меньше 100 ₽ |
| `suggest_raise` | доход вырос: переводим и предлагаем поднять процент |

## Запуск

Нужен только Docker.

```bash
git clone https://github.com/keepmeinyourmind/zapas.git && cd zapas
docker compose up -d --build --wait
```

Поднимутся PostgreSQL, бэкенд (миграции применяются сами) и Swagger UI:
- API: http://localhost:8080 — проверка `curl localhost:8080/health` → `{"status":"ok"}`
- Swagger UI с описанием и кнопкой «Try it out»: http://localhost:8081

Остановить: `docker compose down` (с удалением данных — `docker compose down -v`).

## Демо за 2 минуты

Шесть детерминированных сценариев Ани, 20 лет, студентка: доход около 30 000 ₽, рассрочка за ноутбук 6 000 ₽ 25-го, цель «Подушка», откладывает 10%. Каждый сценарий сбрасывает Аню, загружает её историю за полгода и присылает одно поступление. Одинаковый сценарий всегда даёт одинаковый результат.

| Сценарий | Что пришло | Решение «Запаса» |
|---|---|---|
| `stable` | обычные 30 000 ₽ | `auto` — сам откладывает 3 000 ₽ |
| `income_drop` | 24 000 ₽ вместо 30 000, через 5 дней рассрочка | `ask` — «Доход ниже обычного на 20%. Отложить 1 000 ₽?» |
| `simple_mode` | то же, что `income_drop`, но клиент отказался от анализа | `auto` — молча списывает 2 400 ₽, как обычное автопополнение |
| `self_transfer` | 10 000 ₽ со своей карты другого банка | не доход — решения нет |
| `new_client` | первая зарплата, истории нет | `ask` — «Мы ещё изучаем ваш доход» |
| `income_rise` | 36 000 ₽ третий месяц подряд вместо 30 000 | `suggest_raise` — откладывает 3 600 ₽ и предлагает поднять процент |

Главный сценарий:

```bash
# 1. Пришло меньше обычного — «Запас» не списывает молча, а спрашивает
curl -s -X POST localhost:8080/api/scenarios/income_drop/run

# 2. История решений с причинами
curl -s localhost:8080/api/clients/anya/decisions

# 3. Ответить на вопрос: отложить 1 000 ₽ (id — из ответа шага 1)
curl -s -X POST localhost:8080/api/decisions/<id>/answer -d '{"choice":"amount","amount":100000}'

# 4. Или не отвечать: через 24 часа сработает безопасный вариант
curl -s -X POST localhost:8080/api/debug/advance-time -d '{"hours":25}'

# 5. Состояние копилки
curl -s localhost:8080/api/clients/anya/savings
```

Сравните с `simple_mode` — та же Аня и те же 24 000 ₽, но как у обычного автопополнения: копилка молча списывает 2 400 ₽, и на рассрочку не хватает 1 400 ₽. «Запас» посчитал, что безопасно отложить только 1 000 ₽, и спросил.

```bash
curl -s -X POST localhost:8080/api/scenarios/simple_mode/run
```

Все суммы в API — в копейках (`100000` = 1 000 ₽), время — UTC. Сценарий фиксирует время сервера на 20.10.2026 — оно остаётся таким до перезапуска (`docker compose restart backend`).

## Тесты

```bash
cd src && go test ./...
```

Движок, классификатор, профиль дохода, анкета и тихие часы покрыты table-driven тестами. Интеграционные тесты — повтор транзакции не даёт второго перевода, очередь вопросов, поздний ответ, арест, все сценарии демо — идут с настоящим PostgreSQL:

```bash
docker compose up -d db
docker compose exec db createdb -U zapas zapas_test   # один раз
cd src && TEST_DATABASE_URL='postgres://zapas:zapas@localhost:5433/zapas_test?sslmode=disable' go test -p 1 ./...
```

Тесты очищают базу (`TRUNCATE`), поэтому им нужна отдельная `zapas_test`, а не база демо.

Всё это запускается в CI на каждый пуш, вместе с `docker compose up` и прогоном сценариев (бейдж вверху).

## Архитектура

```
HTTP → internal/api → internal/service ─┬─ internal/classifier   доход ли это
                                        ├─ internal/profile      медиана, доверие, регулярные платежи
                                        ├─ internal/engine       Decide() — чистая функция
                                        └─ internal/storage      PostgreSQL 16
                       internal/domain — общие типы
```

Принципы:
- **Деньги только в копейках** (`domain.Money`, `int64`), никаких `float`.
- **Движок — чистая функция:** без БД и `time.Now()`, время приходит параметром, результат детерминирован.
- **Идемпотентность:** `source_tx_id` уникален, повторное событие не даёт второго перевода.
- **Пороги** (отклонение дохода 15%, буфер) лежат в конфиге.

Стек: Go, стандартный `net/http`, PostgreSQL 16 (`pgx`), миграции `goose`, Docker Compose.

## Настройки

| Переменная | По умолчанию |
|---|---|
| `DATABASE_URL` | `postgres://zapas:zapas@localhost:5433/zapas?sslmode=disable` |
| `HTTP_ADDR` | `:8080` |
| `CORS_ORIGIN` | `http://localhost:5173` |
| `DROP_THRESHOLD_PCT`, `RAISE_THRESHOLD_PCT` | `15` (отклонение дохода, %) |
| `BUFFER_RUB` | `0` (неприкосновенный остаток на карте, ₽) |
| `ONBOARDING_MIN_AGE` | `18` |
| `ONBOARDING_MIN_SCORE` | `40` (порог баллов анкеты из 100) |

Порт базы на хосте — 5433, чтобы не конфликтовать с локальным PostgreSQL на 5432.

Запуск без Docker для разработки (нужен Go 1.27+):

```bash
docker compose up -d db
cd src && go run ./cmd/server
```

## Ограничения MVP

Это демо спринта 1, а не боевой сервис. Что сознательно упрощено и что сделаем дальше:

- **Нет авторизации.** Клиент определяется по `id` в пути. В пилоте клиент приходит из ВТБ Онлайн, и `client_id` берётся из токена банка, а не из URL.
- **`POST /api/transactions` и `POST /api/events/account` — только для систем банка.** Сейчас их может вызвать кто угодно; в пилоте — только сервисы банка с собственной авторизацией.
- **Нет шифрования.** Ни HTTPS, ни TLS к базе (`sslmode=disable`); данные анкеты хранятся открыто. Защита персональных данных — спринт 2.
- **Отладочные адреса открыты.** `/api/debug/advance-time` и `/api/scenarios/*` двигают время и сбрасывают Аню; в пилоте их не будет.
- **Упрощения расчёта:** «обычный доход» — медиана по виду дохода, а не по отправителю; следующий доход ждём через 30 дней после последней регулярной выплаты; повседневные траты — среднее в день за последние 30 дней, а при короткой истории — за сколько есть, но не меньше чем за 7 дней; регулярные платежи — только ежемесячные; пороги подобраны вручную.
- **Учитывается только карта.** Других счетов и банков нет, переводы в копилку — внутри своей базы, а не через API банка; push-уведомлений нет.
